# 哨兵小陀螺控制记录（2026-10-29）

本轮目标是在场地中驱动实际 CAD 哨兵，提高移动速度，并通过 X 开启底盘旋转，同时保持云台世界航向。以下是当时的理想运动方案，后续轮地物理实现见 2026-10-29-wheel-physics.md。

当时保留 gazebo_ros_planar_move，将缓存 CAD 实例拆为底盘和上云台网格，增加连续 yaw 关节及 Gazebo C++ 位置/速度稳定插件，发布实际关节状态和云台世界位姿。Python 键盘程序通过已有看门狗持续发送移动与旋转状态。环境为 ROS Humble、Gazebo Classic 11、C++17、Python 3，继续使用原生 CAD 导入工具。

## 处理顺序

1. 模型：按原生装配边界拆分底盘和上部网格，保持可见 CAD 姿态；转轴取原 big_yaw_joint 的 z=0.051。用底盘方盒碰撞替换圆柱碰撞，移除旧简易圆柱模型。检查组合外观边界、网格单位有限值、出生间隙和关节拓扑。
2. 控制：W/S/A/D 为 0.8 m/s，Q/E 为 1.5 rad/s；X 开启持续 3 rad/s 小陀螺，C 关闭，空格全停。平移 0.3 s 后过期；键盘心跳存在时旋转保持，失联 0.5 s 后停止运动并关闭旋转。平移限幅 1.2 m/s，角速度限幅 4 rad/s。检查重复 X、C、空格、过期输入、非有限数值和较高速度限制。
3. 稳定插件：gimbal_yaw_joint 在小陀螺开启时锁存世界航向，每个仿真步反向转动云台；发布 joint_states 和 gimbal_pose。关闭时保持相对关节角，避免复位跳变。检查角度跨界和实际旋转中的世界航向。
4. 集成：sim_teleop 只组合一次完整场地、机器人、Gazebo 和 RViz 入口。确认库安装路径与依赖，在无界面运行中通过键盘伪终端测试 W/S、X、旋转中平移、C、空格和失联停车，测量实际里程计及 gimbal_pose。
5. 验证和说明：执行包测试、原生角度单元测试、构建与运行检查，记录统一启动命令和按键。保留原始 URDF 与 CAD 来源。

检查重点为 yaw 跨界、重复 X 状态不反转、停车不遗留旋转状态、失联同时停止平移与旋转，以及拆分后 CAD 姿态/实例完整、不重复生成车辆或圆柱、场地完整加载。

## 当时结果

模型拓扑/资源、键盘状态/限幅和 C++ 角度头文件用例均先复现失败，再修复通过。原生构建和九个 CTest 通过。真实键盘伪终端验证了移动、底盘完整一圈旋转、云台世界航向保持和实际停车。

审查发现平移参考应直接使用 /gimbal_pose，不能拼接独立采样的里程计 yaw 与关节角；补充回归后修复。输出边界元数据改为只统计实际输出的非退化三角形，来源边界单独保留。当时未留下待解决的阻断项。
